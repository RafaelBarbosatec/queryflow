# Changelog

The full history lives in
[CHANGELOG.md](https://github.com/RafaelBarbosatec/queryflow/blob/main/CHANGELOG.md).

## 0.7.0

The MySQL driver was upgraded from `mysql_dart 1.2.1` to `3.0.3`.

- **BREAKING:** Queryflow now requires Dart `>= 3.6.0`, the minimum supported by
  `mysql_dart 3.x`.
- MySQL 9 and `caching_sha2_password` authentication support.
- JSON columns are decoded correctly.
- Prepared statements are safer and the driver now serializes concurrent calls
  on a single connection (FIFO).
- Pooled prepared statements use the driver's `withConnection` flow.
- Zero dates (`0000-00-00`) are returned as `null` by default.
- No public Queryflow API changes.

## 0.6.0

This release focuses on correctness, PostgreSQL parity, and safer defaults.

### Query builder

- `UPDATE` now applies **every** `WHERE` condition. Previously only the first
  one was used.
- `DELETE` now joins conditions with `AND`/`OR` and preserves `OR`.
- `notWhere()` negates every matcher (`NOT`, `NOT LIKE`, `NOT IN`,
  `NOT BETWEEN`, `IS NOT NULL`, ...).
- `Equals(null)` and `Different(null)` are translated to `IS NULL` /
  `IS NOT NULL`.
- `In` accepts any value type and rejects empty lists.
- `UPDATE` no longer treats `id` as a special column.
- `INSERT` quotes column names and uses dialect placeholders.

### Transactions

- `executeTransaction()` keeps type adapters and schema definitions, so model
  helpers work inside transactions.
- MySQL transactions no longer require a previous query.
- Nested transactions throw a clear `UnsupportedError`.
- `insertModel()` runs directly on the transaction connection.

### Schema management

- PostgreSQL schema synchronization reads `INFORMATION_SCHEMA` case-insensitively.
- Foreign keys added during synchronization are created correctly.
- `initalData` works on PostgreSQL and respects auto-increment columns.
- `TypeEnum` uses `TEXT` + `CHECK` on PostgreSQL.
- Synchronization errors are thrown instead of silently logged.
- Views are dropped before their tables when `dropTable` is used.
- View synchronization uses the correct PostgreSQL schema.
- `dropObsoleteColumns` is opt-in.
- Added columns keep nullability, defaults, unique, and enum constraints.

### Connections and placeholders

- PostgreSQL accepts `?` placeholders on pooled connections and inside
  transactions. Quoted strings and dollar-quoted blocks are preserved.
- MySQL pooled prepared statements run on the connection that prepared them.
- `close()` is idempotent and connections can be reused after closing.
- PostgreSQL no longer sends `SELECT 1` before every query.

### Inserts

- `insert()` returns the inserted primary key: `RETURNING` on PostgreSQL,
  explicit keys honored on both databases, and a `primaryKey` parameter for
  custom key names.

### API and tooling

- Added `synchronize()` and `executeTransaction()`; the old spellings are
  deprecated aliases.
- Logging is silent by default; pass `debug: true` to enable it.
- `lints` replaces `flutter_lints`; `test` is pinned; CI runs on the Dart SDK.
